# Supabase Auth federation

Clinical SOS uses Supabase Auth as its OpenID Connect identity provider and keeps Base44 as the application session and authorization layer. This preserves the existing Base44 entity permissions and role-protected routes.

## Application behavior

- `/login` starts Base44 SSO when `VITE_SUPABASE_SSO_ENABLED=true`.
- `/auth/supabase` handles Supabase email/password sign-in, registration, confirmation, and password recovery.
- `/auth/supabase/authorize` is the Supabase OAuth authorization UI.
- Both Supabase routes remain disabled until `VITE_SUPABASE_SSO_ENABLED=true`.
- Base44 issues the final app session after Supabase verifies the user. Existing `ProtectedRoute`, `RoleProtectedRoute`, and client-entitlement checks remain authoritative.

## One-time dashboard configuration

1. In Supabase **Authentication > URL Configuration**, set the Site URL to `https://clinical-sos-sync.base44.app` and allow redirects to `https://clinical-sos-sync.base44.app/auth/supabase`.
2. In Supabase **Authentication > Signing Keys**, use an asymmetric signing key (RS256 or ES256). OpenID Connect ID tokens require one.
3. In Supabase **Authentication > OAuth Server**, enable the OAuth server and set the authorization path to `/auth/supabase/authorize`.
4. Register a confidential OAuth client named `Clinical SOS Base44`. Its redirect URI is `https://app.base44.com/api/apps/<BASE44_APP_ID>/auth/sso/callback`.
5. In the Base44 app SSO settings, select manual OIDC and use:
   - Discovery URL: `https://htlyplekracwejhkhttu.supabase.co/auth/v1/.well-known/openid-configuration`
   - Scopes: `openid email profile`
   - The client ID and client secret generated by Supabase
6. Set `VITE_SUPABASE_SSO_ENABLED=true` in the Base44 app environment only after both sides are configured and tested.

Base44 SSO availability depends on the app's Base44 plan. Keep the feature flag disabled until the SSO provider is ready; the existing Base44 login remains available while it is disabled.

## Optional overrides

The repository defaults to the ClinicalSOS Supabase project and its browser-safe publishable key. These variables can override that configuration:

```text
VITE_SUPABASE_URL=https://htlyplekracwejhkhttu.supabase.co
VITE_SUPABASE_PUBLISHABLE_KEY=your_publishable_key
VITE_SUPABASE_SSO_ENABLED=false
```

Never use a Supabase `service_role` or secret key in a `VITE_` variable.
